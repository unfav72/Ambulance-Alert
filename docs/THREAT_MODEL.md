# Application Security Threat Model (STRIDE)

This threat model outlines potential attack vectors against the **Emergency Coordination System** and the architectural controls implemented to mitigate them.

---

## 1. STRIDE Threat Analysis

### 1. Spoofing
- **Threat**: Attacker transmits fabricated GPS coordinates to mislead dispatchers or claim an ambulance is at scene when it is elsewhere.
  - **Mitigation**:
    - Endpoints require authenticated JWT tokens with `AMBULANCE_CREW` role.
    - Active shift verification: user must have an active shift assignment on the vehicle.
    - Physics sanity check: velocity delta between successive observations cannot exceed 180 km/h; teleportation triggers security alert.
    - Timestamp freshness: observations > 120s old or > 15s in the future are rejected.

### 2. Tampering
- **Threat**: Attacker intercepts or modifies emergency priority, bed counts, or dispatch assignments.
  - **Mitigation**:
    - TLS 1.3 encryption in transit for all HTTPS and WebSocket traffic.
    - Zod schema validation on all inputs; unexpected fields are stripped.
    - Database transactions with row-level locks prevent concurrent state tampering.
    - Hospital staff can only modify capacity for their authenticated `organizationId`.

### 3. Repudiation
- **Threat**: Hospital staff denies having diverted an incoming critical patient, or crew denies receiving dispatch.
  - **Mitigation**:
    - Every operational decision, diversion, acceptance, and status change is persisted to the immutable `AuditLog` table.
    - Logs capture `userId`, `action`, `entityId`, `ipAddress`, `userAgent`, and detailed timestamp.
    - Clinical handover requires receiving physician's name, notes, and timestamp.

### 4. Information Disclosure
- **Threat**: Unauthorized users access patient clinical narratives, symptoms, or caller phone numbers.
  - **Mitigation**:
    - Public tracking endpoint (`/track/:caseNumber`) sanitizes response data, returning only vehicle telemetry and milestone states.
    - PWA Service Worker explicitly excludes `/api/*` from caching to avoid storing sensitive medical data in unrestricted browser cache.
    - Role-based scoping prevents patients from querying unassociated incidents.

### 5. Denial of Service (DoS)
- **Threat**: Malicious actor floods emergency intake endpoint to deplete ambulance resources or crash backend.
  - **Mitigation**:
    - Rate limiting middleware:
      - Emergency intake: max 10 requests per 5 minutes per IP.
      - Authentication: max 10 attempts per 15 minutes per IP.
      - GPS telemetry: max 120 updates per minute per vehicle (2Hz).
    - Idempotency key requirement ensures duplicate network retries return existing case without re-triggering allocation.
    - Memory and payload size limited to 1MB per HTTP request.

### 6. Elevation of Privilege
- **Threat**: Public user registers and manipulates request body to assign themselves `SYSTEM_ADMIN` or `DISPATCHER` privileges.
  - **Mitigation**:
    - Public registration endpoint (`/auth/register`) hardcodes role assignment to `PATIENT_REQUESTER`. Any `role` field submitted in request body is ignored by schema.
    - Privileged roles can only be provisioned via cryptographically random (256-bit entropy) invitation tokens generated by an authorized administrator.
